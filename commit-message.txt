Round I (0.5.4): the PlayerPuppet bodies (Character.TPP_Player, the

- New src/plugin/BodySetup.*: registers CoopSystem.OnBodyInitialize with
  Codeware's CallbackSystem (Entity/Initialize, targets
  DynamicEntityTarget.Tag Cp2077Coop.Puppet / CoopMirror). While a body
  is built it adds a gameImpostorComponent (character replica with head)
  to player bodies without one ([puppet] addImpostor, default on), and
  optionally points the root animated component's graph at the local
  V's ([puppet] useVGraph, default off). Bodies are only touched once
  both targets are on; the handler is unregistered if they can't be
  added; the local V is never touched; the singleton is never destroyed
  (it holds a resource reference) and forgets V's graph on world detach.
- AnimCapture recognises the local V by address (player system), so
  spawned PlayerPuppet bodies aren't captured as V.
- Motion inputs default to the round I names; an empty coop.ini value
  means the default, "none" turns one off, "-name" negates.
- Natives: SetBodyOptions/GetBodyOptions, GetMotionInputs,
  OnBodyInitialize. Dev panel: "Copy my look onto it (add an impostor)"
  and "Give it my animation graph", TPP_Player first in the body list,
  checkboxes and motion fields synced from the plugin.
- Review fix before shipping: Red::AsHandle<CoopSystem, IScriptable>
  recursed forever through WeakHandle's conversion operator; the system
  now locks its own weak handle.
- Docs: round I results and round J questions (08), round J steps

Animation capture

  CBaseFunction_Handlers (pointer to the table / the table itself)

  ApplyFeature, SetInput*, PushEvent), where every script-fed input ends;
  calls for other characters are passed on without reading arguments.
  The replication leftovers are only used if those aren't found. Static
  functions are included.

0.5.1 fixed 0.5.0's script compile error (time dilation called on a
GameObject). Everything below is 0.5.0, in case it wasn't committed:

Story co-op for Cyberpunk 2077 2.31 (base game + Phantom Liberty), 2-4
players, Seamless-Co-op style: the host's save owns the world, everyone
keeps their own V, no tether. Start with docs/09-development-handoff.md;
it has the rules, status, architecture map, build and checks, next steps
and the gotchas we already hit. In-game test steps: docs/07.

Puppets: plain NPC + AI walking replaced by "direct drive"
- Body: the game's third-person V (Character.TPP_Player_Cutscene_Male/
  Female), the one matching the local V's body (only that one spawns).
  It still copies the local V's look and weapon (impostor; S1c open).
- Movement: no AI routing. The plugin switches the puppet's AI off
  (CoopSystem.SetPuppetAI -> IComponent.Toggle through RTTI, so a missing
  function logs instead of breaking script compilation), and the bridge
  places it every frame at the interpolated network pose and yaw
  (TeleportationFacility.Teleport, only when it moved/turned/drifted).
  ~0.1 s behind instead of the AI's delay.
- Fallback: a body that stays put while placements move >1 m away from
  it (2 s) goes back to AI walking by itself (M0b behaviour), retries
  direct drive after 60 s or with its next body, and stays on AI walking
  after a second fallback; a body with no AI is respawned instead. The
  AI switch is retried for 3 s. The panel says which mode and why.
  coop.ini [puppet] drive=ai uses AI walking from the start.
- Animation: src/plugin/AnimCapture swaps native handler-table entries of
  the Replicate*/SetAnimationParameter*/PushAnimationEvent functions,
  reads the arguments, keeps inputs aimed at the local V, calls the
  original; restored on unload. New message PlayerAnim (0x0303, protocol
  4): changed inputs at <=15 Hz, every event exactly once, full set every
  2 s for late joiners. Receivers apply them to the puppet's animation
  controller (ApplyFeature, SetInput*, PushEvent).
- Motion values: speed, direction relative to facing, vertical speed,
  turn rate and moving, worked out from the pose (core/AnimMotion.hpp),
  fed into graph inputs named in coop.ini [anim] (empty until round F
  finds the names; settable live from the dev panel).
